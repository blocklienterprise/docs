Blockli Studio hosts an MCP server for coding agents. Once connected, your agent can look up how the Blockli SDK works instead of guessing, check the code it writes against Blockli's rules, and read the runtime logs from your app's live preview.

Use this when you are building your own app from a custom repository in Studio.

Each connection uses a token that belongs to one app. An agent connected with that token can only reach that app.

## What your agent can do

| Area | What the tools provide |
| --- | --- |
| SDK guidance | Which hooks to use, their signatures, the fields each item type has, and recommended patterns. |
| Snippets | Ready-made, typed starting code for list screens, detail screens, app pages, and feeds. |
| Validation | Checks that screens use the SDK correctly before you ship, including sign-in, sign-out, and navigation flow. |
| Your content types | The custom post type sources on your WordPress site and the fields each one exposes. |
| Translations | The app's translatable strings, and a check for hardcoded text. |
| Live preview | Your preview's status, and its recent runtime logs with search. |
| Shipping | Whether a set of changed files can go out as an On-Air Release or needs a new build. |

## Before you start

- Your app in Studio uses a custom repository.
- You can sign in to Studio and open the app's **Development** page.
- For the live preview tools, a live preview must be running. The other tools work without one.

## Step 1 — Generate a token in Studio

1. In Studio, open your app and go to the **Development** page.
2. Find the **Connect Your Coding Agent** card.
3. Click **Generate Token**.
4. Copy the **MCP URL** and the **Token**.

<Warning>
  The token is shown only once. If you lose it, revoke it and generate a new one.
</Warning>

## Step 2 — Add the connection to your agent

In the examples below, replace `YOUR_MCP_URL` and `YOUR_TOKEN` with the values from Studio.

<Tabs>
  <Tab title="Cursor">
    1. In Cursor, open **Cursor Settings** and go to the **MCP** section.
    2. Click **New MCP Server**. Cursor opens its `mcp.json` file.
    3. Add the server:

    ```json
    {
      "mcpServers": {
        "blockli-studio": {
          "url": "YOUR_MCP_URL",
          "headers": {
            "Authorization": "Bearer YOUR_TOKEN"
          }
        }
      }
    }
    ```

    4. Save the file and return to the **MCP** section.
    5. Switch **blockli-studio** on if it is off.

    This file lives in Cursor's own settings on your computer, not in your repository, so the token is never committed.
  </Tab>
  <Tab title="Claude Code">
    Run this command in your terminal:

    ```bash
    claude mcp add --transport http blockli-studio YOUR_MCP_URL --header "Authorization: Bearer YOUR_TOKEN"
    ```

    If your project is based on the Blockli app starter, it already contains a `.mcp.json` file that reads two environment variables. In that case, set them in the terminal where you start Claude Code instead of running the command above:

    ```bash
    export BLOCKLI_MCP_URL=YOUR_MCP_URL
    export BLOCKLI_MCP_TOKEN=YOUR_TOKEN
    ```

    Studio shows these two lines, filled in, as **Shell setup** when you generate a token.
  </Tab>
  <Tab title="Other agents">
    Any agent that supports remote MCP servers over HTTP can connect. Configure it with:

    - **URL:** `YOUR_MCP_URL`
    - **Header:** `Authorization: Bearer YOUR_TOKEN`

    Keep the word `Bearer` and the space before the token.
  </Tab>
</Tabs>

## Verify

Your agent's MCP settings should show **blockli-studio** as connected, with the Blockli tools listed.

Then ask your agent something that needs the tools, for example:

```text
Use the blockli-studio tools to get the active preview for my app and show its recent logs. Then tell me which collections I can list with useCollection.
```

You should get your preview's status, its recent log lines, and the list of collections the SDK supports.

Back in Studio, the **Connect Your Coding Agent** card shows when each token was last used.

## Manage tokens

- **Revoke a token** from the **Connect Your Coding Agent** card. It stops working immediately.
- **Use one token per person or machine**, so you can revoke one without interrupting the others. Each app can have up to 10 active tokens.
- **Treat a token like a password.** Do not paste it into your repository, a pull request, or a chat. Keep it in your agent's settings or in an environment variable.

## Troubleshooting

| What you see | Likely cause | What to do |
| --- | --- | --- |
| The connection fails with an authorization error | The token is wrong, was revoked, or the header is missing `Bearer` and a space before the token. | Check the header. If in doubt, generate a new token. |
| The agent connects but lists no tools | The server is switched off in your agent's MCP settings. | Switch **blockli-studio** on, then reload the agent's tool list. |
| Preview tools report no active preview | No live preview is running for the app. | Start a live preview from the **Development** page, then ask again. |
| Requests are refused as too many | The token is making requests too quickly. | Wait a minute and try again. |
| A tool the agent expects is missing | The agent is asking for a tool that is not part of the Blockli set. | Ask the agent to list the blockli-studio tools and choose from those. |

If the connection still does not work, contact support from inside Studio.
