Use this checklist when setting up a tenant app in Blockli Studio.

## 1. Create the app and connect WordPress

There are two ways to do this — both lead to the same result.

**Option A — Create in Studio first:**

1. Log in to Studio and click **New App**.
2. Enter the **App Name** and click **Create**.
3. In your WordPress admin, go to the **Blockli Mobile App** plugin → **Overview** and click **Connect**.
4. You'll be redirected to Studio. Select the app you just created.
5. Your WordPress URL and connection are set up automatically.

**Option B — Connect from WordPress directly:**

1. In your WordPress admin, go to the **Blockli Mobile App** plugin → **Overview** and click **Connect**.
2. You'll be redirected to Studio. Create a new app from there and enter your **App Name**.
3. The app and connection are set up in one step.

## 2. Connect iOS

In **Store Setup → Credentials → iOS**, fill in your Apple Developer credentials.

### App Store Connect API key

This lets Studio sign your builds, submit to the App Store, and register bundle identifiers.

1. Open [Apple Developer](https://developer.apple.com/account) and note your **Team ID** under **Membership details**.
2. Open [App Store Connect](https://appstoreconnect.apple.com) → **Users and Access → Integrations → App Store Connect API**.
3. Open the **Team Keys** tab. Individual keys don't work with Studio.
4. Copy the **Issuer ID** at the top of the page.
5. Click **\+** to create a key. Name it and set the role to **Admin**.
6. Copy the **Key ID** and download the `.p8` file. Apple only lets you download it once.

Fill in:

- **Apple Team ID**
- **Issuer ID**
- **Key ID**
- **API key (.p8)**

Click **Save & verify**. Studio confirms the connection and shows how many bundle IDs are in your account.

### APNs auth key

Required for iOS push notifications.

1. Open [Apple Developer](https://developer.apple.com/account) → **Certificates, Identifiers & Profiles → Keys**.
2. Click **\+**, name the key, and check **Apple Push Notifications service (APNs)**.
3. Click **Continue → Register**, copy the **Key ID**, and download the `.p8` file.

Fill in:

- **APNs key ID**
- **APNs auth key (.p8)**

<Note>
  One APNs key can be reused across all apps in the same Apple Developer account.
</Note>

### Set the iOS bundle identifier

In the **Blockli project** tab, open the **iOS** section.

- **Pick an existing identifier** — Studio lists the ones in your Apple account. Select the release and test identifiers.
- **Register new identifiers** — choose **Register new…**, enter a name and release identifier (e.g. `com.yourcompany.yourapp`). Studio suggests the test identifier by appending `.test`. Click **Create in Apple Developer**.

Click **Save**.

## 3. Connect Android and Firebase

In **Store Setup → Credentials → Android**, fill in your Firebase credentials.

### Firebase service account JSON

Required for push notifications and app registration.

1. Open [Firebase Console](https://console.firebase.google.com) and select or create a project.
2. Click the **gear icon → Project settings → Service accounts**.
3. Make sure **Firebase Admin SDK** is selected, then click **Generate new private key → Generate key**.
4. Download the JSON file. Google keeps no copy.

Upload it into:

- **Service account (admin SDK) JSON**

Click **Save & verify**. Studio connects to Firebase and lists your Android apps.

### Set the Android package name

In the **Blockli project** tab, open the **Android** section.

- **Pick an existing app** — Studio lists the Android apps in your Firebase project. Select the release and test package names.
- **Register new apps** — choose **Register new…**, enter a nickname and release package name. Studio suggests the test package name by appending `.test`. Click **Create in Firebase**.

Studio registers both apps, generates `google-services.json` automatically, and fills in both fields.

Click **Save**.

<Note>
  You don't need to get or upload `google-services.json` yourself. Studio creates and manages it when you register apps through the Blockli project tab.
</Note>

### Google Play service account (optional)

Only needed for automated Play Store uploads. Skip this if you upload builds manually.

1. Open [Google Cloud Console](https://console.cloud.google.com) and enable the **Google Play Android Developer API** for your project.
2. Go to **IAM & Admin → Service Accounts** and create a new service account.
3. Skip the permission steps — Play permissions are set in Play Console, not here.
4. Open the new account → **Keys** tab → **Add key → Create new key → JSON**. Download the file.
5. In Play Console → **Users and permissions → Invite new users**, paste the service account email and grant release or Admin permissions.

Upload into:

- **Google Play service account (.json)**

Click **Save**.

## 4. Connect WordPress deep links

In **Store Setup → Credentials**, fill out **Deep Links**.

This lets Studio publish App Links and Universal Links files to the tenant WordPress site.

1. Log in to the tenant WordPress admin.
2. Go to **Users → Profile** for an admin user.
3. Create an **Application Password** and copy it immediately.

Fill in:

- **WP username**
- **Application password**

## 5. Add store listing copy

In **Store Setup → Listing**, enter the copy used for App Store and Google Play submissions.

Typical fields include:

- **App Store subtitle**
- **App Store description**
- **Play short description**
- **Play full description**

This is only required when preparing store submissions.

## 6. Build

1. Click **Save** on any unsaved credential tabs.
2. Go to **Build** and start your first build for device testing.
3. Use a production build only when you are ready for store submission.

---

**Credential quick reference:**

| Credential | Purpose | Bundled into app? |
| --- | --- | --- |
| Firebase service account JSON | Push notifications + app registration | No |
| `google-services.json` | Android Firebase config (auto-generated by Studio) | Yes (Android only) |
| Google Play service account JSON | Automated store submission | No |
| App Store Connect API key | iOS signing and App Store upload | No |
| APNs auth key | iOS push notifications | No |
| WordPress application password | Publish deep-link files to tenant site | No |
